# Quake Arena — Godot 4.7.1 multiplayer FPS vertical slice

A self-contained, GDScript-only arena FPS MVP. It uses primitive geometry, a 60 Hz server simulation, 20 Hz snapshots, client prediction/correction, remote interpolation, four weapons, authoritative damage and pickups, automatic respawning, a procedural arena, and a WebSocket transport shared by native and Web clients.

No add-ons, paid assets, native extensions, or external runtime dependencies are used.

## Quick start

Use Godot **4.7.1**. Replace `<GODOT>` below with the editor/executable path.

### Desktop host

1. Import `project.godot` in Godot 4.7.1 and run the project.
2. Enter a name, leave port `8910`, and select **Host Game**.
3. A local authoritative player is created as peer `1`.

Command-line equivalent:

```bash
<GODOT> --path /path/to/quake_arena -- --host --name=Host --port=8910
```

### Dedicated server

```bash
<GODOT> --headless --path /path/to/quake_arena -- --dedicated --port=8910
```

`--server` is accepted as an alias for `--dedicated`. The desktop menu also has an in-process dedicated-server button; Web builds hide it.

### Desktop client

Run another project instance, use address `127.0.0.1`, port `8910`, and select **Join Game**.

```bash
<GODOT> --path /path/to/quake_arena -- --join=ws://127.0.0.1:8910 --name=Client
```

Run additional clients with different names to test the 2–8 player path.

## Controls

| Action | Default |
| --- | --- |
| Move | `W A S D` |
| Jump / auto-bhop timing | `Space` |
| Look | Mouse |
| Fire | Mouse 1 |
| Alternate fire (reserved) | Mouse 2 |
| Previous / next weapon | `Q` / `E`, mouse wheel |
| Railgun / Lightning / Shotgun / Gauntlet | `1` / `2` / `3` / `4` |
| Scoreboard | Hold `Tab` |
| Release mouse / menu | `Esc` |

Click the game view to recapture the mouse. Browsers require pointer capture to originate from a user input event.

## Architecture

The client never submits a transform, hit result, health value, ammo value, score, or pickup state. It submits a monotonically increasing input sequence containing movement, jump, aim, fire intent, and requested weapon. The server clamps movement and aim, rejects stale sequences, applies an input timeout, validates ownership and ammunition, simulates `CharacterBody3D`, performs all physics queries, and broadcasts snapshots.

| Layer | Responsibility |
| --- | --- |
| `NetworkManager` | WebSocket server/client lifecycle and connection signals |
| `GameClient` | Input capture, local prediction, snapshot consumption, remote presentation |
| `GameServer` | Registration, command validation, simulation, spawn/death/respawn, replication |
| `PlayerController` | Shared Quake-inspired acceleration, friction, air control, gravity, jumping |
| `PlayerState` | Server-owned health, armor, inventory, ammo, selected weapon, death state |
| `WeaponSystem` + weapon resources | Fire-rate/ammo validation, authoritative attack ids/seeds, weapon dispatch |
| `DamageSystem` | Armor absorption, knockback, idempotent damage events, lethal decisions |
| `PickupBase` | Server overlap/range validation, effect application, replicated cooldown |
| `MatchManager` | Player names, kills/deaths, farthest-safe spawn selection, scoreboard |

Server physics runs at 60 Hz. Clients send current input once per physics tick. The server broadcasts state at 20 Hz on a separate multiplayer channel. The local native/Web client predicts only against static world collision and blends small server corrections; large divergence snaps to the authoritative state. Remote players interpolate toward snapshot targets.

WebSocket is intentionally used instead of ENet because browsers cannot open ENet/UDP peers. WebSocket is reliable and ordered underneath, so it has more head-of-line latency than a UDP native-only transport, but it provides the simplest dependable shared transport for this 2–8 player MVP.

Short lag compensation is not included. Railgun validation uses the current server state. Crouching and self-damage are also omitted because they were optional; bunny-hopping by holding jump is enabled.

The arena itself is generated by `arena_map.gd`, so every peer constructs identical static geometry without transferring map meshes. It contains central open combat, west/east/north elevated decks, stairs, a southern jump gap and narrow bridge, corridors, cover, eight spawn points, color-coded pickup routes, containment walls, lighting, and a kill volume below the floor.

## Weapons

Weapon tuning lives in editable `.tres` resources under `resources/weapons/`. Every resource exposes damage, range, shots/ticks per second, spread, pellet count, ammo cost, maximum ammo, knockback, and effect duration.

| Weapon | Server behavior | Default tuning |
| --- | --- | --- |
| Railgun | One authoritative long-range ray | 100 damage, 120 m, 0.8 shots/s |
| Lightning Gun | Repeated ray while held | 7 damage/tick, 24 m, 12 ticks/s |
| Shotgun | 10 server rays with a server-created deterministic seed | 9 damage/pellet, 45 m, 6.5° cone |
| Gauntlet | First-hit short ray; walls block it | 50 damage, 2.4 m, 1.25 attacks/s |

Effects are presentation-only replicated dictionaries containing authoritative endpoints. Rail, beam, muzzle, pellet, and impact geometry is generated at runtime and expires automatically.

All four weapons start unlocked so the slice can be tested immediately. Weapon pickups still run the full unlock/refill validation path.

## Health, armor, death, and pickups

- Health and armor default to 100 maximum.
- Armor absorbs 66% of incoming damage until depleted.
- `DamageSystem` records `target + attack_id` for five seconds, preventing the same attack event from damaging a target twice.
- The server marks death, attributes the kill, disables collision, broadcasts the feed, waits three seconds, chooses a spawn farthest from living players, and resets the player.
- Falling into the red void is an authoritative lethal event.
- Health, armor, ammo, and weapon pickups are server-triggered by overlap, verify distance and capacity, update only `PlayerState`, disappear on every peer, and respawn after their configured delay.

## Web export

### Export settings

1. Install the matching **Godot 4.7.1 export templates**.
2. Open the included `Web` preset, which uses:
   - Compatibility renderer / WebGL 2.0.
   - Single-threaded Web export.
   - No extensions or native plug-ins.
   - Output `build/web/index.html`.
3. Export in the editor or run:

```bash
<GODOT> --headless --path /path/to/quake_arena \
  --export-release Web /path/to/quake_arena/build/web/index.html
```

### Serve and test locally

Do not open `index.html` as a `file://` URL. Serve the directory:

```bash
python3 -m http.server 8060 --directory /path/to/quake_arena/build/web
```

Start the dedicated server on the same computer:

```bash
<GODOT> --headless --path /path/to/quake_arena -- --dedicated --port=8910
```

Open `http://127.0.0.1:8060`, enter `127.0.0.1` and port `8910`, then join. The client constructs `ws://127.0.0.1:8910`.

### Production browser connection

An HTTPS page cannot connect to plain `ws://` because browsers block mixed content. Terminate TLS at a reverse proxy and forward the WebSocket upgrade to the plain Godot dedicated server. An Nginx example is included at `deploy/nginx.example.conf`.

In the menu, enter the full public URL, for example:

```text
wss://arena.example.com/socket/
```

When a full `ws://` or `wss://` URL is entered, the separate port field is ignored. The dedicated server should remain bound privately or firewalled; expose only the TLS proxy in production.

The single-threaded preset does **not** need cross-origin-isolation headers. The server must serve `.wasm` as `application/wasm`. If thread support is enabled later, also return:

```text
Cross-Origin-Opener-Policy: same-origin
Cross-Origin-Embedder-Policy: require-corp
```

Browser differences:

- A Web build can join but cannot host or run a dedicated server.
- Web clients use WebSocket, not ENet.
- Pointer lock requires a click; background tabs may be throttled or paused.
- WebGL 2.0 and the Compatibility renderer are required.
- Production HTTPS requires `wss://` with a trusted certificate.

## Verification

Parse/import every referenced scene and script:

```bash
<GODOT> --headless --editor --path /path/to/quake_arena --quit
```

Run the included server gameplay smoke test:

```bash
<GODOT> --headless --path /path/to/quake_arena \
  --script tests/server_gameplay_smoke.gd
```

It exercises all four authoritative weapon paths, ammunition consumption, damage-event deduplication, and server pickup application. A separate live test should still be used for deployment/firewall verification.
